Главный вывод

В проекте две параллельные, конфликтующие реализации одной дизайн-системы — legacy-статик (styles/) и React (src/). React-страницы подключают обе, поэтому один класс красится дважды с разными значениями, а результат зависит от порядка загрузки CSS.

02 · P0

refinement.scss переопределяет токены в слое компонентов

Файл заново задаёт --content-width, --layout-margin и --layout-gutter в :root — поверх токенов. Плюс .home-page { max-width:1600px } в том же файле. Итог — 4 значения ширины макета, побеждает случайное. refinement.scss стал 18 КБ «фиксов поверх всего».

:root { --content-width: 1440px; } /* tokens: 1468px */ .home-page { max-width: 1600px; } /* ещё одно */
03 · P0

Битый токен --lh-md-inline: 10px

Line-height 10px для текста 16px — артефакт экспорта из Figma. Используется в навбаре, пилюлях, кнопках, чипах. Любой перенос строки → текст наезжает; держится только на фиксированной высоте с align-items:center.

.site-nav__link { font: 400 var(--text-md)/ var(--lh-md-inline) ... } .ui-btn-md { font: 400 var(--text-md)/ var(--lh-md-inline) ... }
04 · P2

Нестандартные веса шрифта в обход --fw-*

Токены задают только 400/500/700, но refinement.scss вводит 520, 540, 560, 580, 650, 680, 720. Одинаковые по смыслу заголовки набраны разным весом — это уже не система.

.site-nav__brand { font-weight: 720 } .hero-title-main { font-weight: 680 } .catalog-title { font-weight: 560 }
05 · P1

Футер скопирован дословно в 3 файла

Блоки .home-footer / .footer-* идентичны в design-1-home, design-2-instructors, design-3-profile (по ~80 строк один-в-один), плюс React SiteFooter.scss. Правку футера сейчас надо вносить в 4 местах — при заявленном «едином SiteFooter».

design-1-home.css ┐ design-2-instructors.css ├─ одинаковый .footer-* × 3 design-3-profile.css ┘ + SiteFooter.scss
06 · P1

Две независимые навигации

Система построена на .site-nav* (system.css + React SiteNavbar), но design-1-home.css содержит вторую навигацию: .home-navbar / .nav-link / .dropdown / .caret. Другая разметка, другой дропдаун. Главная выглядит иначе, чем каталог.

.site-nav / .site-nav__trigger ← каталог, профиль .home-navbar / .dropdown / .caret ← только главная
07 · P1

Три системы заголовков одновременно

.section-heading__* (section-heading.css), .kicker + .section-title (base/_typography.scss и повторно в refinement.scss с другими значениями), и shared-faq.css переопределяет заголовок FAQ на font-decor 48px. Kicker в разных секциях то 13px uppercase, то 14px обычный.

kicker: 13px/600/uppercase (refinement) kicker: 14px/500 (base/_typography)
08 · P2

Хардкод вместо токенов

Правило STYLING.md #2 требует var(--token). Нарушается массово: прямые hex (#e9e9e9, #1f1f1f, #51ee6b — при том что есть --green-600), Figma-координаты пикселями и спрайт-аватары на процентах.

grid-template-columns: 332.738px 17.262px 205px ... .avatar img { width: 2538.87%; top: -918.87% }
09 · P0

scripts/ и public/scripts/ разъехались

shared-navbar.js и shared-faq.js существуют в двух каталогах с разным содержимым (разные хеши). Классический источник «на одной странице работает, на другой нет».

scripts/shared-navbar.js @0683707… public/scripts/shared-navbar.js @8a27640… ← ≠

Приоритетный план исправлений

P0 · Убрать двойные источники правды
  1. Один набор токенов (React src/styles/tokens), удалить styles/tokens.css.
  2. Убрать переопределения --content-width из refinement.scss.
  3. Устранить рассинхрон scripts/ ↔ public/scripts/.
P1 · Единые компоненты
  1. Один футер — удалить копии из трёх design-*.css.
  2. Одна навигация .site-nav, удалить .home-navbar.
  3. Один заголовок — свести три системы к одной.
P2 · Гигиена значений
  1. Починить --lh-md-inline (10px → 1/1.2).
  2. Свести веса шрифта к шкале 400/500/600/700.
  3. Заменить Figma-хардкод (px-координаты, %-аватары) на токены и grid-fr.
P3 · Структура сайта
  1. Канонический список 7 категорий и slug'ов.
  2. Дорожная карта для 6 нереализованных разделов.
  3. Решить судьбу legacy: мигрировать и удалить, либо не импортировать в React.
